날짜 상수와 "끝 미포함" 규칙:
  ```python
  START_DATE = "2016-01-01"
  # All collectors treat `end` as exclusive, so this includes 2026-06-30.
  END_DATE = "2026-07-01"
  ```
  - yfinance의 history(start, end)가 [start, end) 반개구간으로 동작하기 때문에,
    특정 날짜까지 포함하려면 end에 그 다음날을 넣어야 함.

버그 수정 1 - Tiingo 캐시가 날짜범위를 확인 안 하던 문제:
  - 예전: 캐시에 그 티커가 "존재하기만" 하면 재수집을 건너뜀 -> 기간을 넓혀
    재수집해도 캐시 때문에 일부 기간이 조용히 누락될 위험.
  - 수정 (TiingoFallback.recover 내부):
    ```python
    start_ts = pd.Timestamp(start)
    last_needed_ts = pd.Timestamp(end) - pd.Timedelta(days=1)
    if len(cached):
        coverage = cached.groupby("Ticker")["Date"].agg(["min", "max"])
        have = set(
            coverage[
                (coverage["min"] <= start_ts) & (coverage["max"] >= last_needed_ts)
            ].index
        )
    else:
        have = set()
    ```

  - Open/Close는 원본 유지, High/Low만 그날 O/H/L/C 중 최댓값/최솟값으로 재계산:

리밸런싱 시점별 자격(Point-in-time Membership) 필터 - 2단계 심화 보정:
  - 문제: "그 종목이 그 날짜에 가격 데이터가 있으면" 무조건 리밸런싱 후보로
    넣고 있었음. 이건 "그 날짜에 실제 S&P500 구성종목이었는지"와 다름.
  - 예시: MRVL(2026-06-22 편입)이 2016년 리밸런싱 스냅샷에도 후보로 잘못 등장.
    OKE는 2001년 편출, 2010년 재편입(여러 번 편입 가능하므로 전체 이력 확인 필요).
  - 검증 결과: rebalance_60df 27,757개 (종목,날짜) 조합 중 6,208개(22.4%)가
    실제로는 그 시점에 구성종목이 아니었던 "위반" 케이스.
  - 새 함수 추가 (src/get_tickers.py):
    ```python
    def filter_by_membership(df, ticker_col="Ticker", date_col="Date",
                              force_refresh=False) -> pd.DataFrame:
        """Keep only rows where ticker_col was an actual S&P 500 member
        on date_col."""
        membership = _load_membership_history(force_refresh)[["ticker", "start_date", "end_date"]]
        merged = df.merge(membership, left_on=ticker_col, right_on="ticker", how="left")
        is_member = (merged[date_col] >= merged["start_date"]) & (
            merged["end_date"].isna() | (merged[date_col] < merged["end_date"])
        )
        merged["_is_member"] = is_member.fillna(False)
        eligible = (
            merged.groupby([ticker_col, date_col])["_is_member"]
            .any().rename("_eligible").reset_index()
        )
        result = df.merge(eligible, on=[ticker_col, date_col], how="left")
        return result.loc[result["_eligible"].fillna(False)].drop(columns="_eligible")
    ```
  - 여러 번 편입/편출된 종목(예: AAL은 1996~1997, 2015~2024 두 구간)도 전체
    이력 중 하나라도 그 날짜를 포함하면 인정하도록 처리.
  - 검증: AET(편출일 2018-11-29) -> 필터 후 마지막 등장 시점 2018-11-09로 정확히 컷.

설계 원칙 정리 (raw 데이터는 안 자르고, 리밸런싱 후보만 필터링):
  - sp500_universe.csv, final_df_raw.parquet, sp500_beta_df.parquet은 날짜
    필터링을 하지 않음 (의도적).
  - 이유: final_df_raw는 60/120일 롤링 피처 계산의 "재료"이므로, 편입 전
    데이터까지 넉넉히 있어야 재편입 시점의 롤링 계산이 정상 작동함.
  - 날짜별 정확한 자격 검증은 오직 리밸런싱 후보 선정 단계(rebalance_60df/120df)

5. 피처 엔지니어링 (src/feature.py)
================================================================================

add_features(prices, sp500_beta_df, windows=(60,120)) 함수가 종목별로 그룹핑해서
각 날짜 기준 과거 N일(60 또는 120)치 데이터로만 지표를 계산.
docstring: "All rolling features use only information available on or before
each row's date." (lookahead bias 원천 차단)

8개 지표:
  - volatility_Nd: 연환산 변동성 (일별 수익률 표준편차 x sqrt(252))
  - mdd_Nd: 최대낙폭 (구간 내 고점 대비 최대 하락률)
  - downside_volatility_Nd: 하방 변동성 (하락일만 골라서 계산)
  - beta_Nd: 시장 베타 (종목-시장 공분산 / 시장분산)
  - ma_gap_Nd: 이동평균 이격도 (종가/이동평균 - 1)
  - rsi_Nd: 상대강도지수 (평균상승/평균하락 비율 기반, 0~100)
  - momentum_Nd / return_Nd: 기간수익률 (완전히 동일한 값, 중복 컬럼!)
  - cagr_10y: 보조지표, 클러스터링에서 제외 (아래 참고)

버그 발견 - momentum과 return이 완전히 동일:
  ```python
  frame[f"momentum_{window}d"] = period_return
  frame[f"return_{window}d"] = period_return   # 같은 값 두 번 저장
  ```
  상관계수 1.0으로 확인됨. return_60d만 남기고 momentum_60d는 제외 결정.

cagr_10y를 클러스터링에서 제외한 이유 (feature.py에 주석으로 남김):
  ```python
  # 보조지표: CAGR, 현재 가격과 10년 전 가격을 이용해 연평균 복합성장률을 계산
  # 참고용으로만 남겨둠 - 클러스터링/모델 피처로는 쓰지 않음
  # - 10년치 과거 데이터가 있어야 값이 나와서 결측률이 매우 높음 (전체 행의 약 95%)
  # - 60/120일 롤링 윈도우와 기준 기간이 달라 다른 피처들과 일관성이 없음
  ```
  (참고: cagr_10y 자체는 rolling shift 방식이라 lookahead bias는 아님. 결측률과
  기간 불일치가 제외 사유.)

왜 리밸런싱이 필요한가:
  - 특정 날짜 하나만 골라 군집화하면 표본 1개 -> 통계적으로 무의미.
  - 60일 간격으로 43개(120일 간격이면 22개) 독립적인 판단 시점을 만들어
    반복 검증해야 "전략을 꾸준히 실행했을 때 통했는가"를 확인 가능.

```python
all_dates = sorted(cluster_60df['Date'].unique())
rebalance_dates = all_dates[::60]
rebalance_snapshots = cluster_60df[cluster_60df['Date'].isin(rebalance_dates)].copy()
```

Drift 검증 (스냅샷 값이 다음 리밸런싱까지 얼마나 어긋나는지):
  - 같은 종목의 이번 값과 직전 값 차이(diff)의 표준편차를, 원본 값의 표준편차로
    나눠서 비율로 비교. 비율이 1에 가깝거나 넘으면 "스냅샷 하나로 그 기간을
    대표하기 위험하다"는 뜻.

  | 지표          | 60일 비율 | 120일 비율 |
  |---------------|-----------|------------|
  | beta          | 0.84      | 0.71       |
  | volatility    | 0.99      | 0.90       |
  | return        | 1.40      | 1.31       |
  | rsi           | 1.24      | 1.11       |

  - 수익률 계열(return/rsi)이 안정성 계열(beta/volatility)보다 훨씬 불안정
    (모멘텀 신호는 원래 지속성이 약하다는 금융 이론과 일치).
  - 120일 윈도우가 60일보다 전반적으로 덜 흔들리지만, 리밸런싱 횟수가
    44개->22개로 절반이 되어 통계적 표본은 줄어드는 트레이드오프.

결정 (2026-08-26): 구조를 미리 복잡하게 바꾸지 않고, 일단 43번(또는 22번)
백테스팅을 먼저 끝까지 돌린다. 결과가 안 좋으면 그때 이 drift를 원인 후보로
검토한다.
