# S&P 500 30/60/120/252일 클러스터링·리밸런싱 데이터

전처리 완료된 S&P 500 10년치 가격 데이터로부터, 클러스터링/백테스팅에 바로 쓸 수
있는 피처·리밸런싱 데이터셋을 만드는 스크립트입니다.

## 실행

```bash
pip install pandas numpy
python build_rebalance_data.py
```

기본 윈도우(30/60/120/252일) 대신 다른 간격을 쓰고 싶으면 `--windows` 옵션에
쉼표로 구분해서 넘기면 됩니다 (코드 수정 불필요).

```bash
python build_rebalance_data.py --windows 45,90
```

`--windows`를 다르게 줘서 여러 번 실행해도 `final_df.parquet`에 예전 윈도우
컬럼이 쌓이지 않도록 처리돼 있습니다(매번 최신 `--windows` 기준으로만 갱신).
다만 이전 실행에서 만든 `rebalance_*df.parquet` 파일 자체는 자동으로
지워지지 않으니, 필요 없어진 파일은 직접 삭제해주세요.

`data/` 폴더에 다음이 생성/갱신됩니다.

- `final_df.parquet` (덮어씀): 원본 OHLCV + 30/60/120/252일 × 4개 지표 = **16개
  피처 컬럼**이 추가된 버전
- `cluster_df.parquet` (신규): `Date`, `Ticker` + 위 16개 피처 컬럼만 남긴 버전
- `rebalance_30df.parquet` / `rebalance_60df.parquet` / `rebalance_120df.parquet`
  / `rebalance_252df.parquet` (신규, 4개): 각각 30/60/120/252일 간격으로
  샘플링한 리밸런싱 시점 스냅샷. 네 파일 모두 **같은 16개 피처 컬럼**을 담고
  있고, **샘플링된 날짜 집합만** 다릅니다. 각 (종목, 날짜)가 그 시점에 실제
  S&P500 구성종목이었는지까지 필터링 완료 — **백테스팅에 바로 사용 가능**

> `python build_rebalance_data.py`를 다시 실행해도 안전합니다(입력 컬럼을
> 새 값으로 덮어쓸 뿐 누적되지 않습니다).

## 피처 윈도우 vs 리밸런싱 간격 — 서로 다른 개념

- **피처 윈도우(30/60/120/252일)**: 같은 날짜에 대해 "과거를 얼마나 길게
  보고 계산했는가"의 차이. 한 행(종목, 날짜)에 16개 컬럼으로 전부 같이 존재
  가능하며 서로 충돌하지 않습니다.
- **리밸런싱 간격**: "어떤 날짜들을 스냅샷으로 남길 것인가"의 차이. 30일
  간격과 252일 간격은 샘플링되는 날짜 집합 자체가 달라서, 파일을 따로 둡니다.
  네 `rebalance_*df` 파일은 날짜 집합만 다를 뿐 피처 컬럼 구성은 동일합니다.

## 피처 설명

다중공선성 분석을 거쳐 확정한 4개 지표입니다 (자세한 근거는 `src/feature.py`
docstring 참고).

| 지표 | 의미 | 역할 |
|---|---|---|
| `beta_Nd` | 시장 베타 | 안정성 (1순위) |
| `volatility_Nd` | 연환산 변동성 | 안정성 (1순위) |
| `return_Nd` | N일 기간 수익률 | 수익률 (2순위) |
| `rsi_Nd` | 상대강도지수 | 수익률 (2순위) |

모든 피처는 그 날짜 이전 데이터만 사용하는 롤링 계산이라 lookahead bias가 없습니다.

## 리밸런싱 시점별 자격 필터가 필요한 이유

"그 날짜에 가격 데이터가 있음"과 "그 날짜에 실제 S&P500 구성종목이었음"은
다릅니다. 예를 들어 어떤 종목이 과거에 지수에서 빠졌다가 최근 재편입됐다면,
가격 데이터는 계속 있지만 재편입 이전 시점에는 후보가 되면 안 됩니다.
`src/membership.py`의 `filter_by_membership()`이 편입/편출 이력을 기준으로
이를 걸러냅니다.
